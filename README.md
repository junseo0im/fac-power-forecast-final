# 제조 생산데이터 기반 전력사용량 예측 및 최대피크 위험조건 분석

제6회 K-인공지능 제조데이터 분석 경진대회 주제 ⑤의 분석 코드입니다. 선박엔진용 볼트·너트 공장의 15분 단위 수요전력(2021-01-01~09-14)으로 **전력을 미리 예측하고, 기본요금을 정하는 피크(최대수요전력)를 놓치지 않도록 경보하는 방법**을 만들고 검증했습니다.

- 노트북은 서면평가 항목 순서(1 데이터 이해·진단 → 2 AI 예측모델 → 3 영향요인·오류분석 → 4 현장 활용 → 6 코드·재현성)로 번호를 붙였습니다.
- 모든 노트북에는 실행 결과가 저장되어 있어, 실행하지 않고도 읽을 수 있습니다.
- **결과보고서**: [REPORT.md](REPORT.md) · **팀**: 서울메이트 (임준서, 이태연)
- 이 공개 저장소에는 원자료와 실제 전력값이 들어 있는 파일을 올리지 않았습니다(아래 '공개 저장소에서 뺀 파일').

## 1. 핵심 결과

**데이터 진단** — 1~6월은 하루 전력 96칸이 다른 날과 완전히 같은 '복사 기록'이 월 55~100%였고, 7월 6%, 8~9월 0%였습니다(01-1, 표 t03). 그래서 분석은 **7/1 이후 실측 구간**으로 하고, 8/9~9/14를 1주씩 5번 '과거로 학습해 미래로 시험'했습니다(01-2).

**예측 정확도(15분 전력, 5주 시험)** — 02-2

| 예측 | 최종 모델 | MAE (kW) | 출처 |
|---|---|---|---|
| 하루 앞(전날 자정) | 생산계획 기반 기준 곡선(하루 종류 × 전날 가동 × 시각별 평균) | 7.32 | 표 t10 |
| 1시간 앞(매 정시) | 선형 회귀(기준 곡선 + 현재 편차)와 Chronos-2의 평균 | 5.85 | 표 t16 |

**같은 기준의 시간 단위 비교(시간 최대 = 15분 4칸 중 최댓값, 1~5주차)** — 02-4, 표 h04

| 예측 | 15분 최종 모델 | 시간 최대 Chronos-2 | 차이의 95% 신뢰구간(하루 단위 부트스트랩) |
|---|---|---|---|
| 1시간 앞 MAE | 5.853 | 5.780 | −0.515 ~ 0.405 (차이 없음) |
| 1시간 앞 **피크 시간** MAE | 9.951 | **7.677** | −3.362 ~ −1.378 (시간 최대 모델이 유의하게 작음) |
| 하루 앞 MAE | 7.064 | 6.891(+ 공변량) | −0.792 ~ 0.446 (차이 없음) |

**피크 위험 확률·경보(1시간 앞, 1시간 단위, 2~5주차, 피크 42시간)** — 02-4, 표 h01·h02

| 경보 방법 | 재현율 | 정밀도 | F1 |
|---|---|---|---|
| 15분 모델 예측 ≥ 178.7kW(기본 경보) | 0.833 | 0.372 | **0.515** |
| 시간 최대 Chronos-2 예측 ≥ 178.7kW(재현율 우선 경보) | **0.976** | 0.328 | 0.491 |
| 시간 최대 피크 분류기(클래스 가중 LightGBM + isotonic 보정) | 0.810 | 0.252 | 0.384 |
| 스태킹(분류기·분위수 확률·점예측 결합) | 0.357 | 0.306 | 0.330 |

- 위 표는 1시간 단위로 센 값입니다. 15분 칸 단위로 세면 기본 경보의 재현율은 0.77, 정밀도는 0.19입니다(02-3, 표 t20).

- 기본 경보와 재현율 우선 경보의 F1 차이는 우연 범위였고, 분류기·스태킹은 기본 경보보다 유의하게 낮았습니다(표 h02). 재현율 우선 경보는 피크 42시간 중 41시간을 잡는 대신 헛경보가 59건에서 84건으로 늘어납니다(표 h01).
- 피크 기준 188.7kW는 학습 기간 최대(222kW)의 85%, 준비선 178.7kW는 1주차로 정한 여유값 10kW입니다(02-3).

**영향요인·오류 조건** — 02-3, 03-1
- 1시간 앞 피크 판단은 직전 흐름(1시간 전 시간 피크, 직전 15분 값), 하루 앞은 같은 요일·시각의 과거 패턴·시각·생산계획이 좌우했고, 상호작용은 대부분 '시각'과 함께 나타났습니다(표 e01·e02).
- 오류는 모두 평일 가동일에서 생겼고, 헛경보는 08시 기동과 09~11시·13~16시에 몰렸습니다(표 e05~e07).

**현장 활용** — 04-1, 04-2
- 평일 위험 시간대(08~12시, 13~16시)에 옮길 수 있는 부하 10%를 옮기는 고정 규칙으로 여름 최대가 222kW에서 203.5kW로 줄고, 2021년 선택Ⅰ 요금 기준 연 기본요금이 약 160만 원 줄어드는 것으로 계산되었습니다. 요금제를 선택Ⅱ로 함께 바꾸면 연 약 346만 원입니다(표 t29·t30·t37, 계약 조건 가정).
- 매시 판단과 질의응답을 하는 피크 관리 도우미(규칙 기반)를 만들었습니다(04-2).

## 4. 실행 방법

1. **환경**(Python 3.12.14, CPU)
   ```
   python -m venv .venv
   .venv/Scripts/python -m pip install -r requirements.txt      # macOS·Linux: .venv/bin/python
   ```
   conda를 쓰면 `conda env create -f environment.yml`.
2. **전체 실행**(프로젝트 루트에서)
   ```
   python run_all.py                  # 01-1 → 06 노트북을 처음부터 실행(02-1·02-1b·02-1c는 저장된 예측 사용)
   python run_all.py --with-chronos   # 02-1·02-1b·02-1c의 예측도 다시 계산(CPU로 수 시간)
   python run_all.py --appendix       # 부록 노트북도 저장된 결과로 다시 실행
   python run_all.py --check          # 실행 전후 결과표 비교
   ```
   - Chronos-2 가중치(`amazon/chronos-2`, `autogluon/chronos-2-small`)는 처음 쓸 때 Hugging Face에서 받습니다(`--with-chronos`, `--appendix`에 인터넷 필요). 미리 받아 두려면
     `python -c "from huggingface_hub import snapshot_download as d; d('amazon/chronos-2'); d('autogluon/chronos-2-small')"`
   - `run_all.py`는 노트북을 자기를 실행한 파이썬(위에서 만든 환경)으로 돌립니다.
3. **부록 모델 재학습**(선택, CPU 기준 하루 이상): `appendix/hourly_max_pipeline/run_all.py --mode full --retrain`

- 부록 표 73개 중 달라진 표는 M24 1개로, 실행 장치(CPU 이름)를 적는 열만 다릅니다.

## 공개 저장소에서 뺀 파일

대회 제출 zip에는 들어 있지만, 원자료 재배포를 피하려고 이 저장소에서는 뺀 파일입니다. 원자료를 넣고 `run_all.py`를 실행하면 다시 만들어집니다.

| 뺀 파일 | 이유 |
|---|---|
| `data/raw/`, `data/processed/` | 출제 데이터와 그 전처리 결과 (받는 방법: [data/README.md](data/README.md)) |
| `data/external/` | 외부 공개 자료(CC BY 4.0). 출처에서 받는 방법은 [data/README.md](data/README.md) |
| `outputs/predictions/`의 `final_*`, `pred_*`, `test_predictions.csv`, `decision_log.csv`, `outputs/preds/` | 실제 전력값이 함께 들어 있음 (예측값만 있는 `chronos_*`, `extra_*`는 올림) |
| 부록 `outputs/preds/`, `outputs/submission/`, 표 `step6_*`·`shap_features_*` | 실제 전력값이 함께 들어 있음 |

노트북 중 원자료 행이 그대로 보이는 셀 몇 개는 출력을 지웠습니다. 부록 노트북을 저장된 결과로 다시 실행하려면 위 부록 파일이 필요하므로, 제출 zip을 쓰거나 부록 파이프라인을 다시 학습해야 합니다.

## 7. 한계

- 15분 모델과 시간 최대 모델 모두 9월까지의 결과를 본 뒤 설정이 정해졌습니다. 02-4의 비교는 '같은 조건에서의 비교'이며, 새 기간에서는 성능이 다를 수 있습니다. 02-2 3-7에서 앞 주 결과만으로 매주 다시 모델을 고르게 하면 2~5주차 MAE가 하루 앞 7.72, 1시간 앞 5.87kW로, 5주 결과로 고른 최종 모델의 같은 기간 MAE(7.63, 5.72kW)보다 0.09·0.15kW 컸습니다. 이 정도가 선택 편향의 크기입니다(표 t58).
- 02-1b의 NHITS·TFT와 02-1c의 미세조정은 CPU 시간 때문에 학습량을 줄인 설정의 결과입니다. 이 설정에서 최종 모델보다 나은 후보는 없었지만, 더 길게 학습한 경우는 확인하지 못했습니다(표 t57).
- 평가 기간의 피크는 42시간(2~5주차)뿐이라 경보 지표의 신뢰구간이 넓습니다.
- 시간 단위 비교에서 15분 모델의 '4칸 예측의 최대'는 실제 시간 최대보다 낮게 나오기 쉬워, 시간 최대를 직접 예측하는 모델에 다소 유리합니다.
- 부록 파이프라인은 1~8월 전체로 학습했으며, 이후 진단(01-1)에서 1~6월에 복사 기록이 많다는 것이 확인되었습니다. 부록 결과는 참고로 봅니다.
- 부록의 'LoRA 미세조정' 결과는 실행 환경에 `peft`가 없어 chronos-2-small 전체 미세조정으로 실행된 결과입니다(부록 노트북에 표시). 02-1c는 `peft`로 LoRA 학습했음을 노트북 출력으로 확인했습니다(학습한 파라미터 1.00%).
- 기본요금 절감액은 2021년 요금표와 선택Ⅰ 계약을 가정한 추정이며, 실제 계약·겨울 최대전력을 확인해야 합니다.
