# 제조 생산데이터 기반 전력사용량 예측 및 최대피크 위험조건 분석

제6회 K-인공지능 제조데이터 분석 경진대회(KAMP) 주제 ⑤의 분석 코드와 결과보고서입니다. 선박 엔진용 볼트·너트 공장의 15분 전력을 예측하고, 기본요금을 정하는 최대피크를 낮추는 운영 방법을 제안합니다.

- **프로젝트명**: 생산계획 기반 15분 전력 예측과 피크 저감 운영안
- **팀**: 서울메이트 (임준서, 이태연)
- **결과보고서**: [REPORT.md](REPORT.md)

## 방법론 요약

### 1. 문제 정의

공장의 전기 기본요금은 15분 평균 전력의 최댓값(최대수요전력)으로 정해지고, 여름에 생긴 한 번의 피크가 이후 최대 12개월 동안 반영됩니다. 그래서 평균 정확도와 함께 **요금을 정하는 피크를 언제 놓치는지**를 끝까지 따라갔습니다. 하루 앞 예측은 다음 날 작업 배치에, 1시간 앞 예측은 당일 경보에 씁니다.

![요일별 15분 전력 곡선](outputs/figures/f05_하루_전력곡선.png)

### 2. 데이터 진단

품질 점수는 96.6점이었지만, 1~9월 257일 중 160일(62%)이 다른 날과 하루 전력이 완전히 같은 반복 기록이었습니다. 반복 기록이 몰린 1~6월을 섞으면 같은 시험 기간의 오차가 7.60에서 13.52kW로 커집니다. 실제로 측정된 7~9월만 쓰고, 과거로 학습해 미래로 시험하는 5주 시간순 평가를 설계했습니다.

![다른 날과 전력 기록이 똑같은 날의 예](outputs/figures/f02_복사된날_비교.png)

### 3. 예측 모델

전력은 '오늘 가동하는가'와 '몇 시인가'로 대부분 정해집니다. 달력 대신 생산계획으로 가동 여부를 구분하자 하루 앞 오차가 14.47에서 7.32kW로 절반이 됐습니다. 단순 기준부터 LightGBM, 통계 모델(MSTL·ARIMA), 딥러닝(NHITS·TFT), 사전학습 모델 Chronos-2와 다른 공장 자료로 미세조정한 Chronos-2까지 같은 5주 평가에서 비교했고, 날짜 단위 부트스트랩과 Diebold–Mariano 검정으로 개선이 확인될 때만 더 복잡한 모델을 택했습니다.

| 예측 | 최종 모델 | MAE |
|---|---|---|
| 하루 앞 | 생산계획 기반 기준 곡선(하루 종류 × 전날 가동 × 시각별 과거 평균) | 7.32kW |
| 1시간 앞 | 선형 회귀(기준 곡선 + 0.53 × 현재 편차)와 Chronos-2의 평균 | 5.85kW |

앞 주 결과만으로 매주 다시 모델을 고르면 2~5주차 MAE가 0.09·0.15kW 커져, 같은 기간으로 모델을 고른 데 따른 선택 편향도 작았습니다.

![최종 예측·경보 구조](outputs/figures/f31_모델_구조.png)

### 4. 오차와 피크 조건

오차는 평일 주간, 특히 대체공휴일 가동이나 휴무 직후처럼 평소와 다르게 운영한 날에 몰렸습니다. 피크는 평일 08~16시와 월요일 오전 기동 때 생깁니다. 1시간 앞 경보는 피크 구간의 77%를 미리 알렸고, 같은 재현율의 단순 규칙보다 경보 구간이 44% 적었습니다(15분 구간 기준). 반면 하루 앞 예측으로는 '피크가 넘는 날'을 가려내지 못해(AUC 0.42), 요금을 정하는 피크를 예측에만 맡길 수 없다는 결론을 냈습니다.

![하루 종류·시각별 예측 오차](outputs/figures/f18_오차_히트맵.png)

### 5. 피크 저감 운영안

피크는 '평일 위험 시간대(08~12시, 13~16시)에는 배치형 작업을 하지 않는다'는 고정 규칙이 막고, 예측은 옮긴 작업의 배치와 당일 경보에 씁니다. 옮길 수 있는 부하를 10%로 가정하면 여름 최대가 222kW에서 203.5kW로 줄어 기본요금이 연 약 160만 원 줄고, 요금제를 선택Ⅱ로 함께 바꾸면 연 약 346만 원입니다(2021년 요금표, 계약 조건 가정). 주의일(월요일·휴무 직후)만 반드시 지키면 다른 날 규칙을 일부 놓쳐도 절감이 사라지는 경우가 없었습니다(몬테카를로 4,000회).

![피크 저감 시뮬레이션](outputs/figures/f22_피크저감_시뮬레이션.png)

## 노트북

| 노트북 | 내용 |
|---|---|
| `01-1_데이터_구조와_품질진단` | 변수 의미, 품질 지수, 반복 기록·시각 오류·계측 중단, 전력 사용 패턴 |
| `01-2_전처리와_검증전략` | 정리 규칙, 생산계획 기반 하루 종류, 5주 시간순 평가 설계 |
| `02-1_사전학습모델_Chronos2` | Chronos-2 하루 앞·1시간 앞 예측 |
| `02-1b_딥러닝_통계모델_예측` | MSTL·ARIMA·NHITS·TFT 예측 |
| `02-1c_외부자료_Chronos2_미세조정` | 다른 공장의 15분 전력으로 Chronos-2 LoRA 미세조정 |
| `02-2_15분_예측모델_비교와_선정` | 모델 비교, 부트스트랩·DM 검정, 선택 편향 점검, 최종 모델과 구조도 |
| `02-3_피크기준_경보와_오류분석` | 피크 기준, 경보, 오류·영향요인(SHAP), 예측구간 |
| `02-4_피크위험확률_모델비교` | 시간 최대 모델과 피크 위험 확률 모델 비교 |
| `03-1_실험모델_영향요인과_오류분석` | 실험 모델의 영향요인과 놓친 피크·헛경보 조건 |
| `04-1_피크저감_운영안` | 위험 시간대 규칙, 받는 시간 최적화, 몬테카를로, 요금·ESS 판단 |
| `04-2_피크관리_도우미` | 매시 판단 기록과 규칙 기반 질의응답 (`peak_helper.py`) |
| `06_테스트_예측결과_생성` | 제출용 테스트 예측결과 파일 생성과 대조 |

모든 노트북에는 실행 결과가 저장되어 있어 실행하지 않고도 읽을 수 있습니다. 부록 `appendix/hourly_max_pipeline/`에는 1시간 최대를 직접 예측한 별도 파이프라인(모델 15종 이상 비교)이 있습니다.

## 실행 방법

Python 3.12.14, CPU 환경 기준입니다.

```
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # macOS·Linux: .venv/bin/python
python run_all.py            # 전체 실행(약 10분, 02-1 계열은 저장된 예측 사용)
python run_all.py --check    # 실행 전후 결과표 비교
python -m pytest tests -q    # 자동 점검
```

원자료는 [data/README.md](data/README.md)대로 받아 `data/raw/`에 둡니다. 예측 재계산(`--with-chronos`), 부록 실행, 실행 시간과 재현성 확인 결과는 [docs/실행과_재현성.md](docs/실행과_재현성.md)에 있습니다.
